3. FUNCIONALIDADES IMPLEMENTADAS
- Promociones: selección JPG/JPEG, PNG o WEBP de hasta 5 MB, vista previa,
  reemplazo/eliminación y almacenamiento mediante el servicio de imágenes
  existente. La imagen se conserva en la promoción y la página Anuncio existente
  de la tienda muestra las imágenes de promociones activas.
- Selección de promoción: filtros combinables por género (hombre, mujer,
  unisex, todos) y presentación (30, 50, 100 ml, todas). Se muestran resultados,
  conteos y productos incluidos; se pueden combinar filtros con selección
  manual, quitar productos y limpiar la selección. Las promociones nuevas
  quedan limitadas a la selección; las promociones anteriores sin selección
  conservan su comportamiento global.
- Ventas presenciales: nombre y teléfono opcionales, requeridos en pareja.
  Los pedidos existentes se usan para reutilizar clientes por teléfono y el
  módulo de clientes agrupa sus ventas para consultar fechas, artículos,
  cantidades y totales. Las ventas sin cliente siguen aceptándose.
- Se conservan los cambios locales preexistentes en el módulo de ventas
  presenciales incluidos al generar este instalador.

4. CAMBIOS EN BACKEND
- Se amplió el almacenamiento de imágenes compartido para guardar imágenes de
  promociones en GitHub configurado o en la carpeta local de cargas.
- POST/PUT /api/promociones aceptan opcionalmente multipart/form-data con
  "promocion" (JSON) e "imagen"; también aceptan JSON existente. La respuesta
  incluye img y seleccionEspecifica.
- POST /api/admin/ventas-presenciales acepta opcionalmente
  cliente: { nombre, telefono }.
- GET /api/admin/clientes incluye clientes de ventas presenciales agrupados por
  teléfono; GET /api/admin/clientes/:email/pedidos conserva compatibilidad y
  también resuelve los identificadores por teléfono.
- No se añadieron endpoints nuevos ni una tabla de clientes: los registros de
  clientes se derivan de los pedidos, como en la arquitectura existente.

5. CAMBIOS EN POSTGRESQL
- Se agregan las columnas nullable "img" y "seleccionEspecifica" a
  "promocions". Los registros existentes conservan comportamiento global con
  seleccionEspecifica = false.
- No se eliminan tablas, columnas ni registros. No se ejecutó una migración
  contra la base de datos configurada en este entorno.

6. MIGRACIÓN
- El servidor aplica las columnas de forma idempotente al iniciar.
- Alternativamente, desde PowerShell y la raíz del repositorio:
  psql $env:DATA_BASE_URL -f backend\migrations\20261112-add-promotion-image-and-specific-selection.sql
- Desplegar/reiniciar el backend actualizado antes de usar las funciones del
  instalador que requieren estos cambios.

7. ENDPOINTS

9. PROBLEMAS / LIMITACIONES
- El backend debe desplegarse para que el instalador pueda usar las funciones
  nuevas contra el servicio remoto.
- La persistencia en GitHub para despliegues requiere configurar las variables
  GITHUB_* existentes. Sin ellas se utiliza almacenamiento local del backend,
  sujeto a la persistencia que ofrezca ese servidor.
- No se probó la instalación interactiva ni se validó visualmente la tienda con
  datos del servicio desplegado.
